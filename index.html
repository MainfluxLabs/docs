Mainflux#

Mainflux is an open-source IoT platform that connects devices, manages them across organizations, and turns their data into action.

Devices publish over HTTP, MQTT, WebSocket and CoAP, and receive commands over MQTT, WebSocket and CoAP. Where data cannot be pushed, Mainflux pulls it: it polls Modbus TCP equipment and external HTTP APIs on a schedule. Historical data arrives through CSV and JSON import, and files through the Filestore API.

Every incoming message can be stored for querying, evaluated by rules that raise alarms and send email or SMS notifications, and forwarded to external systems through webhooks.

Features#

Connectivity#

  • Messaging — publish-subscribe messaging with subtopics, and commands to individual things or entire groups.
  • Modbus — scheduled Modbus TCP polling that reads or writes registers and coils and publishes the values.
  • Downlinks — scheduled HTTP requests to external APIs, with each response published as a message of the thing.

Security and Access Control#

  • Certs — X.509 certificates for mTLS on HTTP, MQTT and WebSocket; CoAP uses DTLS with pre-shared keys.
  • Users — user accounts with self-registration, platform invites and OAuth login.
  • Authentication — JWT-based keys for all user-facing operations.
  • Authorization — role-based access control at organization and group level.

Device Management#

  • Provisioning — organizations, groups, profiles and things managed through the HTTP API.
  • Shadows — reported and desired state of each thing, readable and settable while the thing is offline.
  • OTA — over-the-air firmware rollout to things, with per-thing progress reporting.

Data#

  • Storage — message persistence in TimescaleDB, with PostgreSQL as an optional add-on, and an HTTP API for querying stored messages.
  • Converters — bulk import of CSV and JSON files as platform messages.
  • Filestore — file upload and storage for things and groups on the local filesystem or SeaweedFS.

Processing and Notifications#

  • Rules — threshold and Lua script conditions evaluated on incoming messages.
  • Alarms — persisted alarms raised by rule actions.
  • Notifiers — email notifications over SMTP and SMS notifications over SMPP.

Integration#

  • Webhooks — real-time delivery of device messages to external systems as HTTP POST requests.
  • UIConfigs — JSON configuration objects for dashboards and frontends, scoped to organizations, groups and things.

Operations#

  • Audit — audit trail of events from all services, queryable through a read-only API.
  • Tracing — distributed tracing of all services with Jaeger.
  • Backup and Restore — export and restore of users, organizations, things and messages.
